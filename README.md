# からだ記録

毎日のからだ・食事・運動を端末内に記録し、減量の経過を振り返る個人用アプリです。外部API・外部データベース・外部ライブラリ・解析サービスは使いません。GitHubへのコミット・Push・公開設定の変更は行っていません。

## Windowsで開く

アプリのファイルを保存したフォルダーで `index.html` をダブルクリックし、EdgeやChromeで開いてください。インストールやビルドは不要です。

開発用の `preview.ps1` が手元にある場合は、そのフォルダーのPowerShellで次を実行しても確認できます。

```powershell
.\preview.ps1
```

表示された `http://127.0.0.1:8766/` をブラウザで開きます。終了はPowerShellで `Ctrl+C` です。サーバーはこのPC内だけで動き、アプリの9ファイルだけを提供します。Windowsのセキュリティ設定を変更する必要はありません。

**ファイルを直接開く場合、確認用アドレス、GitHub Pagesでは保存場所が異なります。** 移すときは元の画面でJSONを書き出し、移動先で復元してください。ファイルを直接開いた場合、ブラウザによって保存や自動コピーを使えないことがあります。

## 毎日の入力

日付は当日を初期表示します。記録日をD日とすると、対象日は次のとおりです。画面には実際の日付を表示します。

| 対象日 | 項目 |
| --- | --- |
| D日朝 | 体重・体脂肪率・ウエスト・起床時の疲労度 |
| D−1日（前日） | 日種別「ト・へき・きき」、P・F・C、筋トレ、有酸素、アルコール、便通 |
| D−1日夜〜D日朝 | 睡眠時間。集計では起床したD日を使います |

例：11月2日の記録には、11月2日朝の測定値と疲労度、11月1日の食事・運動・日種別、11月1日夜から11月2日朝の睡眠を入力します。

- 日付以外に少なくとも1項目を入力してください。日付だけでは保存できません。
- 筋トレ・有酸素は、0以上の整数（分）です。空欄で保存すると0分になります。運動の種類は自由メモに書けます。
- 記録そのものがない日は未記録です。運動0分の記録を自動で作ることはありません。
- 食事時刻は廃止しました。
- PFCはグラム、睡眠は時間です。7時間30分なら7.5と入力します。
- PFCが3項目そろうと `P×4＋F×9＋C×4` でカロリーを計算します。空欄と0は区別します。
- 疲労度は1（元気）〜5（とても疲れた）です。
- 同じ記録日の保存は、確認後にその日の記録全体を置き換えます。保存前にページを閉じると、入力途中の内容は失われます。

「履歴」から全項目の確認・編集・削除ができます。履歴は記録日Dで並び、月の絞り込みも記録日Dを使います。編集時の日付は固定です。食事・活動の対象日と睡眠期間も表示します。

## 振り返る

従来の身体測定グラフ、基準日を選ぶ7日平均、月別平均も使えます。グラフは体重・体脂肪率・ウエストを切り替えられ、数値表でも確認できます。未記録の測定値は補完しません。

**「期間比較・週次分析」の基準日は、保存済みの最新記録日です。** 上部で選ぶ基準日とは独立しています。

### 7・14・28日の比較

各期間を開くと、直近平均・その直前の同日数の平均・差・有効記録日数を表示します。2期間は重なりません。差は「直近−前期間」です。

最新記録日がDなら、7日間の身体・睡眠・疲労度はD−6〜D、食事・運動・日種別はD−7〜D−1です。14・28日も同じ考え方です。運動は実施日数・合計分・実施日平均を表示し、0分の日は実施日平均の分母から外します。

### 週次分析

1週間は月曜日〜日曜日です。最新記録日が属する週を進行中とし、その前の8完了週も表示します。月曜朝の記録にある日曜の食事・運動は前週に入ります。

身体測定には完了週同士の前週比を表示します。今週の途中経過の前週比は「比較不可」です。今週の分母には未来を含めません。月曜日なら身体は1日、食事・運動はまだ0日が対象です。実施日数・合計時間を、完了した7日間と単純比較しないでください。

### 記録不足の表示

各項目の有効記録日数が対象日数の70%未満なら「記録不足・参考値」です。7日なら4日以下、14日なら9日以下、28日なら19日以下です。0件は「データなし」、比較先がないときは「比較不可」です。

上部の7日平均は選択した基準日をDとして、身体はDまで、食事・運動はD−1までを使います。月別平均は選択した月全体です。新しい期間分析は保存済み最新記録日が基準なので、各画面の対象日を確認してください。横長の表は表の中でスクロールできます。

## PFC目標を設定する

「振り返る」→「PFC目標と変更履歴」→「目標を変更する」を開きます。

| 日種別 | P | F | C |
| --- | --- | --- | --- |
| ト | 150〜160g | 60〜70g | 270〜300g |
| へき | 140〜150g | 50〜60g | 200〜220g |
| きき | 140〜150g | 50〜60g | 200〜220g |

1. 適用開始日を指定します。**食事実施日（D−1）です。**
2. 必要なら「この日に適用中の目標を読み込む」で、適用中の値を入力欄に反映します。
3. 各日種別のPFC下限・上限を編集します。
4. 「確認して目標履歴に追加」を押し、確認画面で確定します。

同じ適用開始日の重複、負数、下限が上限を超える設定は保存できません。変更は新しい開始日を持つ設定として追加し、既存履歴は残します。初回変更より前の期間は初期目標を使います。過去の日を適用開始日にすると、その日以降の達成率も再計算されます。

日種別ごとにP・F・C別と総合の達成率を表示します。範囲内（上下限を含む）が達成です。PFC別はその項目の入力がある日、総合は3項目すべてが入力された日が判定対象です。日種別未選択は除外します。達成日数／判定日数、不足日数・不足日平均g、超過日数・超過日平均gを併記し、不足と超過を相殺しません。

## ChatGPT分析用データをコピーする

「振り返る」の「ChatGPT分析用データをコピー」を押し、必要なときに自分でChatGPTへ貼り付けます。コピーだけでは外部に送信しません。

コピー内容は、最新記録日までの7暦日の詳細、7・14・28日比較、8完了週と今週、PFC目標履歴と達成状況、分析依頼文です。欠損日は「未記録」として残します。**自由メモと食事時刻は含みません。** アルコールなどの記録は含むため、貼り付け前に確認してください。

コピー文章は短い日本語の表形式です。未記録の週は日付と状態を1行、空の前期間は「比較不可」とまとめます。PFCの判定対象がない日種別もまとめますが、データのある項目の数値・有効日数・記録不足・達成率・不足超過量は残します。目標履歴は1か所だけに表示します。
`—` はデータなし、`有効1/7日` は記録充足状況、`100%(1/1日)` は目標の達成率です。これらの分母は異なります。コピー用の数値を丸める処理は加えていません。

自動コピーできなかった場合、画面に手動コピー用テキストが出ます。「テキストを選択」を押して、ブラウザのコピー操作を使ってください。データ0件の場合はボタンが無効になります。アプリが目標を自動変更することもありません。

## JSON・CSVと旧データ

- 記録の保存キーは従来の `karada-log.records.v1` のままです。
- 保存するJSON形式は**バージョン2**です。`records`と`targetHistory`を1つのJSONに含めて端末内に保存します。
- バージョン1の旧保存データ・JSONも読み込めます。読み込むだけでは元の保存領域を書き換えません。保存・削除・目標追加・復元を確定すると新形式で保存します。
- 旧食事時刻は取り込みません。
- 旧有酸素の文字列は、時間を推測せず自由メモに残し、数値は未確定（null）にします。画面に案内し、集計から除外します。
- 旧運動時間の空欄も、実績が不明なので勝手に0にせず未確定のままにします。旧筋トレに小数があれば丸めずメモに残します。
- 未確定欄を編集して空欄のまま保存した場合は、案内のとおり0分になります。必要な分数を確認してから保存してください。
- 新形式で保存したJSONを旧バージョンのアプリへ戻すことはできません。更新前の旧JSONも別に保管してください。

### バックアップと復元

「バックアップ」→「JSONで保存」で記録と目標履歴を保存します。CSVは記録の一覧確認用で、目標履歴は含みません。CSVの列から食事時刻を廃止し、有酸素は分数になりました。日本語向けUTF-8 BOMと、表計算ソフトの数式対策を含みます。

復元するときは、先に現在のJSONを保存してから、次を選びます。

- 記録：今の記録に追加（同じ日付は上書き）／記録をすべて置き換え。
- 目標履歴：現在の履歴を保持（標準）／追加（開始日重複は拒否）／ファイルの履歴に置き換え。

確認画面には、記録の件数と目標履歴の扱いを表示します。旧形式のJSONには目標履歴がないため、「置き換え」を選ぶと初期目標に戻ります。標準の「保持」では既存目標を消しません。破損データや不正な履歴を含むファイルは全体を拒否し、一部だけを復元しません。上限は20MB・50,000記録・5,000目標設定です。

## プライバシーとデータ保護

健康記録と目標履歴はこの端末のこのブラウザ内だけに保存し、自動同期・自動送信しません。定期的にJSONを書き出してください。端末故障、ブラウザデータ削除、Safariによる保存領域整理などで失われる場合があります。プライベートブラウズを避け、バックアップの保存完了を確認してください。アプリ独自の暗号化やパスワード保護はありません。

読み込みに失敗しても、元データを自動初期化・上書きしません。別タブの変更を検知した場合も上書き防止のため操作を停止します。普段は1つのタブで使ってください。

GitHub Pages上ではプログラムの取得通信は発生しますが、健康記録をそこに含める処理はありません。オフラインでの再起動は保証しません。iPhone Safari実機の最終確認は利用者が行ってください。

## ファイルと公開予定

公開・コミット・Pushはまだ行っていません。将来アップロードする予定は次の12ファイルです。

```text
.gitignore
.nojekyll
README.md
index.html
style.css
core.js
analysis.js
analysis-ui.js
app.js
icon.svg
apple-touch-icon.png
icon-512.png
```

`core.js`は検証・保存形式・目標履歴、`analysis.js`は集計と分析文、`analysis-ui.js`は目標・分析・コピー画面、`app.js`は従来画面の操作を担当します。

アイコン素材とアプリ名は維持しています。SVGをアプリ内とファビコン、180px PNGをiPhoneホーム画面、512px PNGを代替ファビコンに使います。

`preview.ps1`、`tests/`、`TESTING.md`、個人のJSON・CSV・認証情報はアップロード対象外です。`.gitignore`は手動アップロードや登録済みファイルまで防ぐものではありません。公開時には上の一覧と照合してください。

## 開発用テスト

Node.jsを使える環境で、手元のテストを次で実行できます。普段のアプリ利用にNode.jsは不要です。

```text
node tests/core.test.cjs
node tests/analysis.test.cjs
node tests/app-startup.test.cjs
node tests/copy.test.cjs
node tests/analysis-text.test.cjs
```

すべて架空データを使用し、実際のブラウザ保存領域にはアクセスしません。結果と確認範囲は `TESTING.md` を参照してください。
