# からだ記録

自分のペースで、毎日のからだと暮らしを残す個人用アプリです。
HTML・CSS・JavaScriptだけで動きます。アカウント登録、アプリ用の有料サービス、外部ライブラリは不要です。

**現在はローカルの試作品です。GitHubへのアップロードや一般公開は行っていません。**

## まずWindowsで試す

1. エクスプローラーで、このアプリのファイルを保存したフォルダーを開きます。
2. `index.html` をダブルクリックして、EdgeまたはChromeで開きます。
3. 「記録する」で日付と、体重など好きな項目を入力します。
4. 「この日の記録を保存」を押します。
5. 「履歴」で保存内容を確認します。一度ページを再読み込みして、記録が残っていることも確認してください。

インストールやコマンド入力なしで試せます。ファイルから直接開く場合の保存動作はブラウザによって異なります。保存エラーが出る場合は、下の確認用サーバーを使ってください。
試し入力には架空の値を使ってください。最初から入っている健康記録はありません。

### Windowsの確認用サーバー（開発用ファイルが手元にある場合だけ）

`preview.ps1` は開発者が手元で確認するためのファイルです。GitHubへのアップロード対象から除外しているため、GitHubから取得したアプリには含まれません。手元にこのファイルがある場合だけ、次の方法も使えます。

このフォルダーでPowerShellを開いて、次を実行します。

```powershell
.\preview.ps1
```

`Local: http://127.0.0.1:8766/` と表示されたら、そのアドレスをブラウザで開きます。
終了するときは、実行したPowerShellで `Ctrl+C` を押します。
スクリプト実行が禁止されているという表示が出た場合、Windowsのセキュリティ設定を変更する必要はありません。まずファイルを直接開く方法を使ってください。

確認用サーバーはこのPC内からだけ接続でき、アプリの7ファイル（画面・CSS・JavaScript・アイコン素材）だけを読み出します。iPhoneからはこのアドレスに接続できません。GitHub Pagesでの公開は別途行います。

**直接開いたファイル、確認用アドレス、GitHub Pagesは、それぞれ別の保存場所になります。** データを移すときは、元の画面でJSONを書き出し、移動先の画面で復元してください。

## 画面の使い方

### 記録日と、各項目の対象日

記録日をD日とすると、次のルールで入力・表示・集計します。

| 対象 | 項目 |
| --- | --- |
| D日当日朝 | 体重・体脂肪率・ウエスト・起床時の疲労度 |
| D−1日（前日）1日分 | PFC・食事時刻・筋トレ・有酸素運動・アルコール・便通 |
| 前日夜〜D日朝 | 睡眠時間。集計では起床したD日を使います |

たとえば2026年11月2日の記録には、11月2日朝の測定値・疲労度、11月1日の食事・活動、11月1日夜〜11月2日朝の睡眠を入力します。記録日を変えると、各欄の対象日も自動で変わります。

保存済みの記録にも同じ読み方を適用します。保存日付や値を自動で移動・変更することはありません。集計の対象日を正しく扱うようになったため、以前とPFC・筋トレなどの平均が変わる場合があります。

### 記録する

- 日付だけは必須です。日付以外に少なくとも1項目を入力してください。
- 日種別は「ト」「へき」「きき」から選べます。意味の推測や自動変換は行いません。
- 体重、体脂肪率、ウエスト、タンパク質P、脂質F、炭水化物C、睡眠時間、疲労度、朝食・昼食・夕食の時刻、筋トレ時間、有酸素運動、アルコール、便通、自由メモを記録できます。
- P・F・Cはグラムで入力します。3項目がそろうと `P×4＋F×9＋C×4` で摂取カロリーを表示します。
- 空欄は「未記録」です。実際にゼロだった項目には `0` を入力します。空欄をゼロとみなすことはありません。
- 疲労度は1（元気）〜5（とても疲れた）です。
- 入力欄は「当日朝の測定・疲労度」「前日の食事と栄養」「前日の活動・生活」「前夜から当日朝の睡眠」に分かれています。日付の初期値は従来どおり当日です。
- 睡眠は時間単位です。7時間30分なら `7.5` と入力します。
- 有酸素運動とアルコールは、種類・量・時間などを自由に書けます。何もなかった日には「なし」と書けます。
- 保存するまでは記録に反映されません。保存前にページを閉じたり再読み込みしたりすると、入力中の内容は失われます。
- 1日につき1件保存します。同じ日付がある場合は、上書き確認が出ます。空欄に戻した項目も含め、その日の記録全体が置き換わります。

### 振り返る

- 「直近7日間の平均」は、基準日を含む7暦日間です。7件の記録という意味ではありません。
- たとえば基準日が11月2日なら、実際の対象日が10月27日〜11月2日の値を集計します。身体測定・疲労度・睡眠は10月27日〜11月2日の記録、PFC・筋トレなどは10月28日〜11月3日の記録内にある前日分が対象です。
- 上の3枚のカードは身体測定の平均です。「食事・活動・睡眠も含めた7日平均を見る」を開くと、PFC・カロリー・筋トレ時間・睡眠・疲労度も確認できます。
- 各項目に入力がある日だけを平均します。未記録日や、その項目が空欄の日は除外します。`0` は含めます。
- 平均と一緒に、計算に使用した日数も表示します。記録がない場合は `—` です。
- グラフは体重・体脂肪率・ウエストを切り替えられます。期間は7日、30日、90日、すべてです。測定日Dを使い、基準日より未来の測定は含めません。
- グラフの横軸は実際の日付の間隔です。未記録日は補完せず、測定した点の間に線を引きます。
- グラフ下の「数値を表で見る」から正確な数値を確認できます。
- 月別平均は、実際の対象日が選択した月に入る値を集計します。7日平均の基準日とは独立しています。PFC・カロリー・睡眠なども確認できます。
- 月別平均も項目ごとの対象日を使います。11月のPFCには12月1日の記録（11月30日分）を含み、11月1日の記録（10月31日分）は含みません。1月1日の記録のPFCは前年12月に入ります。睡眠と疲労度は記録日Dの月に入ります。
- 有酸素運動やアルコールは自由記述のため、数値の平均には含めません。履歴に前日の対象日を添えて表示します。
- カロリー平均には、P・F・Cのすべてが入力されている日だけを使用します。

### 履歴

- 新しい記録日Dから順に表示します。記録日の月で絞り込むこともできます。食事・活動の実際の対象日による月別平均とは、絞り込みの基準が異なります。
- 各記録に、当日朝・前日の食事と活動・睡眠期間を表示します。「すべての項目を見る」では各項目にも対象日が付きます。
- 「すべての項目を見る」で、食事時刻やメモなども確認できます。
- 「編集」を押すと、保存済みの内容が入力画面に入ります。「変更を保存」と確認操作で反映します。
- 編集中の日付は固定です。日付を間違えた場合は、正しい日付で保存して内容を確認してから、間違えた日付の記録を削除してください。
- 「削除」を押すと、対象の日付を確認してから削除します。
- 多くの記録がある場合は、30件ずつ表示します。

### バックアップ

**復元に使うのはJSONです。CSVだけではこのアプリに戻せません。**

1. 「バックアップ」を開きます。
2. 「JSONで保存」を押します。
3. 保存先に `karada-log-日付.json` ができたことを確認します。
4. iPhoneでは、表示されたファイルを共有メニューなどから「ファイルに保存」します。操作はSafariのバージョンによって異なる場合があります。

週に一度や機種変更前など、定期的に保存してください。同じ日に再保存すると、ブラウザがファイル名に番号を付ける場合があります。復元には内容と保存日時を確認したファイルを使ってください。

復元するとき：

1. 先に、現在の記録をJSONで保存します。
2. 復元方法を選びます。
   - **今の記録に追加**：ファイルにない日付の記録は残り、同じ日付はファイル内の内容に置き換わります。
   - **すべて置き換え**：現在の記録をすべて取り除き、ファイル内の記録だけにします。空のJSONなら記録は0件になります。
3. 「JSONファイルを選ぶ」で、このアプリが出力したJSONを選びます。
4. 件数・上書きの有無を確認し、「確認して復元」を押します。「やめる」なら変更しません。

壊れたJSON、異常な値、日付の重複、非対応のバージョンは受け付けません。ファイルの一部だけを復元することもありません。上限は20MB・50,000件です。

「CSVで保存」は、Excelなどで一覧を確認するために使えます。日本語向けのUTF-8 BOM付きです。自由記述が表計算ソフトで数式として実行されないよう、危険な先頭文字にアポストロフィを付けて書き出します。元のメモはJSONにそのまま保存されます。

JSONの構造・形式番号、ブラウザの保存キー、CSVの列順と「日付」の値は従来どおりです。JSON・CSVの「日付」は記録日Dです。前日分の項目を読むときは、その前日の日付として扱ってください。以前のJSONバックアップも引き続き復元できます。

## 記録の保存場所とプライバシー

- 健康記録は、利用中の端末・ブラウザの `localStorage`（ブラウザ内の保存領域）だけに保存します。
- 健康記録をGitHubや外部サーバーに送信する処理はありません。
- 外部API、外部スクリプト、解析ツール、外部フォントは使いません。グラフもアプリ内で描画します。
- 通信制限設定（CSP）の `connect-src 'none'` でも、アプリからのAPI通信などを禁止しています。
- GitHub Pagesで使うとき、ページやプログラムの取得のためにGitHub側との通信は発生します。健康記録をその通信に含める処理はありません。
- データは端末間・ブラウザ間で自動同期しません。Windowsの記録が自動でiPhoneに現れることはありません。
- ブラウザのデータ削除、端末故障、保存容量不足などで失われることがあります。プライベートブラウズを避け、JSONバックアップを保管してください。
- 端末内のデータとJSON・CSVは、このアプリでは暗号化しません。端末を共有する場合やファイルの保管先に注意してください。
- ソースコードには実際の健康記録を入れないでください。アプリを公開しても、端末内の保存記録はソースコードには入りません。
- `.gitignore` はJSON・CSVなどの誤登録を防ぐための補助です。手動アップロードや強制追加まで防ぐものではありません。公開時にはファイル一覧を確認してください。
- 保存データを読み取れない場合、元データの上書きを防ぐため保存・復元・削除を停止します。サイトの保存データを削除せず、状態を確認してください。
- 別タブでデータが変更されたときも、上書きを防ぐため再読み込みを促します。普段は1つのタブで使ってください。

## iPhoneで毎日使うとき

公開後、GitHub PagesのHTTPSアドレスをSafariの通常のタブで開きます。画面下の4つのメニューから操作できます。入力欄は16px以上、ボタンは原則44px以上の高さにし、細い画面でも操作しやすくしています。

今回の試作品は、オフライン専用アプリとしてのインストールや、オフラインでの再起動を保証していません。ページを開くときにはインターネット接続を使ってください。日々の健康記録自体は端末内に保存します。

## GitHub Pagesの公開準備

**公開作業はまだしていません。ユーザーによる確認後に行います。**

ビルド（公開用に変換する作業）は不要です。公開する際は、同じフォルダーに次のファイルがある状態にします。

- `index.html`
- `style.css`
- `core.js`
- `app.js`
- `icon.svg`
- `apple-touch-icon.png`
- `icon-512.png`
- `.nojekyll`

すべての参照先を相対パスにしているため、GitHub Pagesのリポジトリ名付きアドレスでも使える構成です。
JSON・CSVのバックアップや個人の記録ファイルはアップロードしないでください。公開用リポジトリの設定と料金条件を確認したうえで、GitHub Pagesでリポジトリのルートを公開元に指定する想定です。
設定画面の詳細は、公開すると決めた段階で一緒に確認できます。

### GitHubへアップロードする予定のファイル

このアプリでは、次の10ファイルだけをアップロードする予定です。

```text
.gitignore
.nojekyll
README.md
index.html
style.css
core.js
app.js
icon.svg
apple-touch-icon.png
icon-512.png
```

開発用の `preview.ps1`、`tests/`、`TESTING.md` は手元だけに残します。個人のJSON・CSVバックアップ、認証情報、秘密鍵、端末固有の設定も `.gitignore` で除外します。個人ファイルを置く場合は、アプリのフォルダーの外に保管するか、除外対象の `backups/`・`private/` を使ってください。

`.gitignore` は、Gitで新しいファイルを登録するときの除外ルールです。GitHubの画面からの手動アップロード、強制的な追加、すでにGitで管理されているファイルには効かないため、アップロード時には上の10ファイルと照らし合わせて確認してください。

### アプリ名とアイコン

ブラウザのタイトルとiPhoneホーム画面向けの表示名は「からだ記録」です。指定のアイコン素材は、背景色 `#2E7D5A` と白いカレンダー・チェックマークのデザインです。
`icon.svg` をブラウザのファビコンとアプリ内ロゴに使い、`icon-512.png` をPNG形式の代替ファビコンに使います。iPhoneホーム画面用には、HTMLから180×180ピクセルの `apple-touch-icon.png` を参照しています。
すでにホーム画面へ追加済みの場合、名前やアイコンの変更がすぐに反映されないことがあります。ホーム画面上の見え方はiPhone Safari実機で確認してください。

## 開発用テスト（普段の利用では不要）

開発用の `tests/core.test.cjs` が手元にあり、Node.jsが使える環境なら、以下で計算処理のテストを実行できます。テストファイルはGitHubへのアップロード対象外です。アプリ自体の利用にNode.jsは必要ありません。

```text
node tests/core.test.cjs
node tests/app-startup.test.cjs
```

テストは実際のブラウザ保存領域を読み書きせず、架空のデータをメモリー上で扱います。
`tests/legacy-v1.json` は、変更前のプログラムで作成した架空データの互換性確認用ファイルです。`tests/`全体がアップロード対象外です。
